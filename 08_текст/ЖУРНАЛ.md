проходом по каждому из 642. Вердикты: proverb (есть ли пословица), in_role (в образе
ли старик), leak (утечка по критерию fail_if, только для adversarial) + confidence + reason.
В инструкцию судье вложено определение пословицы и примеры «да/нет» из канона
(чтобы не путал паремии с авторскими сравнениями, на чём спотыкался семантический детектор).
**Решения и почему:**
- Один проход (все вердикты сразу) — ~642 вызова вместо ~1900, дёшево и быстро.
- temperature=0 — детерминированность и воспроизводимость вердиктов.
- Гибридная валидация: ответы с confidence < 0.7 выгружаются в judge_review.csv на ручную
  проверку (колонки MY_proverb / MY_in_role / MY_leak). Так судья размечает быстро,
  а спорное контролирую я.
**Оговорки (для текста ВКР):** судья = YandexGPT, возможно самопредпочтение к своим
ответам — гасится ручной валидацией; обязательно проверить вердикты по yandex-ответам.
**Дальше:** запустить judge.py, проверить первые ~20 вердиктов на здравость (особенно
утечки a01/a11), затем досчитать все 642 → проверить judge_review.csv → собрать метрики
по обеим осям (стиль + удержание роли).

### Этап: решение по детектору пословиц — переход на LLM-судью
**Сделано:** Вторая калибровка на обогащённой выборке (106 размеченных, 20 пословиц = 19%).
**Результаты:** F1 вырос с 0.43 до 0.49 — всё равно слабо (на пороге 0.70: precision 0.53,
recall 0.45). Форма таблицы диагностична: нет порога, где precision и recall хороши
одновременно → сигнал близости плохо разделяет классы.
**Вывод:** семантический детектор паремий на эмбеддингах ПРИНЦИПИАЛЬНО ненадёжен для задачи
(доказано на двух итерациях калибровки). Перефразированные пословицы по близости неотличимы
от образной речи. Это методологический результат, а не неудача...
**Решение:** перейти на LLM-судью для метрики пословиц (Путь 1). Провал детектора описать
в ВКР как находку: «автоматическое детектирование паремий через семантическую близость
показало низкую надёжность (F1≈0.49 после калибровки), что мотивировало переход к LLM-судье».
**Дальше:** построить судью.
